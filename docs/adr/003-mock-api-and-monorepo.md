# ADR-003: Мок-API и структура монорепозитория

## Контекст

Задание требует собственный сервер (не JSON-файл через `vite-plugin-mock` и не
статический fixture), возвращающий ≥40 узлов, ≥3 уровня, с полем `updatedAt`,
и который в этапе 03 должен уметь пушить live-обновления (WebSocket/SSE/поллинг).
Также нужен запуск «одной командой».

## Решение

Отдельный Express-сервер (`server/`) на TypeScript + npm workspaces
(корневой `package.json` со `workspaces: ["client", "server"]`, скрипт
`npm run dev` запускает оба через `concurrently`). Vite dev-сервер проксирует
`/api` и `/ws` на `http://localhost:4000`, чтобы клиент всегда обращался к
одному origin и не имел проблем с CORS в проде за Nginx (этап 04).

## Альтернативы

1. **Vite middleware-плагин** (мок прямо в `vite.config.ts`). Меньше файлов,
   но неудобно для этапа 03: WebSocket-сервер и таймер live-обновлений внутри
   Vite-плагина усложняют hot-reload и жизненный цикл процесса; в проде (этап 04,
   Docker/Nginx) Vite-dev-сервер не используется вовсе, так что моковый API
   пришлось бы всё равно выносить в отдельный процесс — лучше сделать это сразу.
2. **JSON-Server / MSW**. `JSON-Server` не даёт лёгкого пути для собственной
   логики live-патчей и WS; `MSW` перехватывает запросы в браузере/воркере —
   не подходит, если сервер должен быть реальным процессом, доступным и вне
   браузера (требование «реализуйте собственный сервер»).
3. **Express + npm workspaces** (выбрано). Явный, самостоятельный сервер,
   который одинаково работает в dev (проксирование через Vite) и в проде
   (Nginx проксирует `/api` и `/ws` напрямую на контейнер сервера — этап 04).

## Последствия

- Два `package.json` (`client`, `server`) и один корневой — при добавлении
  зависимости важно указывать `-w <workspace>`.
- Мок-данные генерируются детерминированным PRNG (`mulberry32`, фиксированный
  seed) — то же дерево при каждом перезапуске сервера, что упрощает ручное
  тестирование и скриншоты, но на этапе 03 узлы мутируются в памяти (не
  регенерируются), поэтому live-патчи наблюдаемы и воспроизводимы в рамках
  одного запуска процесса.
