# ADR-004: Режим просмотра (дерево/таблица) и модель сортировки

## Контекст

Задание допускает два равноценных варианта UI: переключатель «Дерево / Таблица»
ИЛИ split-view при ширине ≥1280px. Также задан специфичный жест сортировки:
обычный клик по заголовку сортирует, двойной клик — сортирует в обратном порядке.

## Решение

**Режим просмотра.** Не выбирать один из двух вариантов, а реализовать оба через
чистый CSS: `Panel` всегда в DOM, видимость управляется пропом `$visible`
(производным от состояния переключателя) на узких экранах, но с
`@media (min-width: 1280px) { display: block }`, которая перекрывает `$visible`
и показывает обе панели одновременно. Сам переключатель скрывается той же
медиа-запросью на ≥1280px, где он избыточен.

**Сортировка.** Клик по заголовку сразу выставляет сортировку по этому столбцу
по возрастанию (`asc`). Двойной клик выставляет по убыванию (`desc`) — не
тоггл, а прямое присвоение. Учитывая, что браузер генерирует для одного
двойного клика последовательность `click, click, dblclick`, `onClick`
успевает сработать дважды (оставляя `asc` неизменным), а `onDoubleClick`
задаёт `desc` — итоговое поведение при двойном клике всегда однозначно
«обратный порядок», без скрытого состояния тоггла, которое могло бы разойтись
с тем, что видит пользователь.

## Альтернативы

1. **Только переключатель** (`useState<'tree'|'table'>`, без split-view).
   Проще, но не использует доступную ширину экрана на десктопе и не
   соответствует явно упомянутому в задании варианту split-view.
2. **Тоггл сортировки на одном клике** (клик — asc, повторный клик по тому же
   столбцу — desc, как в большинстве таблиц). Это стандартный паттерн, но
   задание прямо называет именно двойной клик триггером обратного порядка —
   реализация через одиночный повторный клик не соответствовала бы
   формулировке требования буквально.

## Последствия

- Оба режима (дерево и таблица) всегда смонтированы в DOM на ≥1280px —
  небольшой лишний рендер по сравнению с полностью условным рендерингом, но
  зато состояние (раскрытые узлы, скролл таблицы) не сбрасывается при ресайзе
  окна через порог 1280px.
- Двойной клик по заголовку не поддерживает «вернуть по возрастанию» одним
  дальнейшим двойным кликом (он снова даст `desc`) — для возврата к `asc`
  нужен одиночный клик. Это осознанный трейд-офф в пользу простоты и
  буквального соответствия формулировке задания.
