# ADR-006: Height-transition дерева и клавиатурная навигация таблицы

## Контекст

Задание требует: анимацию раскрытия дерева через height transition (с
уважением `prefers-reduced-motion`) и клавиатурную навигацию по таблице
(стрелки, Home/End, Enter).

## Решение

**Height transition без JS-измерения.** `Branch` (`OrgTree.tsx`) — всегда в
DOM (не размонтируется при сворачивании), `display: grid` с
`grid-template-rows: ${expanded ? '1fr' : '0fr'}` и `overflow: hidden`.
Переход `grid-template-rows` анимируется нативно и корректно сжимает контент
произвольной (динамической) высоты до нуля — без `height: auto`, который
CSS не умеет анимировать, и без измерения `scrollHeight` через ref/эффект.
`@media (prefers-reduced-motion: reduce) { transition: none }` отключает
анимацию (как и у существующего поворота шеврона из этапа 01).

**Клавиатурная навигация — состояние, не DOM-фокус.** Один `tabIndex={0}` на
`<table role="grid">`, `focusedIndex` — обычный React state; стрелки/Home/End
двигают индекс, Enter вызывает `onSelect` для текущей строки. Визуально
активная строка получает `outline` и `aria-activedescendant` на таблице
указывает на её `id`. Индекс не привязан к DOM-фокусу отдельных `<tr>`
(roving tabindex по строкам) — с одним фокусируемым контейнером проще
гарантировать, что фокус не «убегает» при пересортировке/фильтрации.

## Альтернативы

1. **JS-измерение высоты** (`scrollHeight` в ref + `useLayoutEffect`,
   переключение `max-height`). Работает в большинстве браузеров, но требует
   пересчёта при изменении контента (ресайз окна, live-патчи меняющие текст)
   и лишний проход layout на каждое раскрытие/сворачивание.
2. **Roving `tabIndex`** (каждая `<tr>` имеет `tabIndex={-1|0}`, фокус
   передаётся через `.focus()` в эффекте). Более «нативно» с точки зрения
   доступности (реальный DOM-фокус вместо `aria-activedescendant`), но
   сложнее синхронизировать с сортировкой/фильтром (перестроение списка строк
   может отфокусировать элемент, которого больше нет). Выбранный подход
   (единый контейнер + `aria-activedescendant`) — стандартный паттерн для
   `role="grid"`/`listbox` именно по этой причине.

## Последствия

- `Branch` всегда рендерит все узлы поддерева (даже свёрнутые, просто с
  нулевой видимой высотой) — при ~60 узлах это не создаёt заметной нагрузки;
  при существенно большем дереве это стало бы поводом для виртуализации
  (вне рамок этого задания).
- `focusedIndex` не переживает пересортировку/фильтрацию по смыслу (позиция
  «третья строка» — не тот же узел после ресортировки), только по индексу —
  это ожидаемое поведение для табличной клавиатурной навигации (аналогично
  большинству grid-виджетов) и не относится к выбору (`selectedId`), который
  привязан к id узла и переживает любые сортировки.
