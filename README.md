# Staff Pulse

Дашборд для мониторинга орг-структуры компании: дивизионы → отделы → команды,
с интерактивным деревом и аналитической таблицей.

## Стек

- **Клиент**: React 19 + TypeScript + Vite, `@tanstack/react-query` (кэш/SWR),
  `zod` (валидация ответа API), `styled-components` (стилизация).
- **Сервер**: Node.js + Express (mock API), TypeScript, `ws` (WebSocket-сервер для live-обновлений).
- Монорепозиторий на npm workspaces (`client/`, `server/`).

## Запуск (одна команда)

Требуется Node.js 20+.

```bash
npm install
npm run dev
```

Поднимет одновременно:
- сервер на `http://localhost:4000` (`GET /api/org-tree`, WS на `/ws`)
- клиент на `http://localhost:5173` (проксирует `/api` и `/ws` на сервер)

Сервер раз в 2-5 секунд случайно меняет headcount/budget/performance одного
узла и шлёт патч всем подключённым клиентам — раскройте дерево или таблицу и
подождите несколько секунд, чтобы увидеть live-обновление (жёлтая вспышка на
затронутом узле и его предках, индикатор «Live» в шапке).

### Полезные dev-параметры мок-сервера

Для ручной проверки состояний загрузки/ошибки/пустого ответа:

```
GET /api/org-tree?scenario=empty   # пустой массив
GET /api/org-tree?scenario=error   # 500
GET /api/org-tree?delay=2000       # искусственная задержка, мс
```

## Этапы (коммиты)

Каждый этап — отдельный коммит, помеченный тегом `step/N`.

- [x] `step/1` — FOUNDATION: скаффолд, mock API, дерево
- [x] `step/2` — CORE: аналитическая таблица
- [x] `step/3` — POLISH: live-обновления, UX
- [ ] `step/4` — BONUS: Docker, Nginx, AI-поиск

## Тесты

```bash
npm run test -w client
```

- `aggregate.test.ts` — суммирование headcount/budget по узлу и всем потомкам,
  взвешенное по headcount усреднение performance, назначение уровней, пустое дерево.
- `liveUpdate.test.ts` — `applyLivePatch` трогает только затронутый узел и его
  предков (не соседние ветки), корректно пересчитывает их totals, сохраняет
  ссылочную идентичность нетронутых поддеревьев, обновляет `nodesById` под
  клонированные узлы для следующего патча.

## AI в разработке

Проект разрабатывался с использованием **Claude Code** (Anthropic, модель Claude Sonnet 5)
как основного AI-инструмента на протяжении всей работы — от скаффолда до документации.

**Что генерировалось AI:**
- Полный скаффолд проекта (Vite/React/TS клиент, Express-сервер, npm workspaces).
- Генератор мок-данных орг-дерева (`server/src/data.ts`) — детерминированный PRNG,
  ≥40 узлов, 3 уровня вложенности.
- Слой валидации API (`zod`-схемы) и слой кэширования (`@tanstack/react-query`,
  `staleTime: 5000`).
- Компоненты дерева (`OrgTree`, `TreeRow`), состояния загрузки/ошибки/пустого ответа,
  индикатор эффективности.
- Функция агрегации (`aggregate.ts`) и её unit-тесты, аналитическая таблица
  (`OrgTable`) с сортировкой/фильтром/дебаунсом, переключатель Дерево/Таблица
  со split-view на ≥1280px, синхронизация выбора между деревом и таблицей.
- WebSocket-сервер live-обновлений (`server/src/live.ts`), клиентский слой
  инкрементального пересчёта агрегатов (`liveUpdate.ts`, `useLiveOrgData.ts`)
  и его unit-тесты, переподключение с экспоненциальным backoff
  (`liveSocket.ts`), height-transition анимация дерева, клавиатурная
  навигация таблицы.
- Вся документация (`README.md`, `docs/architecture.md`, `docs/data-model.md`, ADR).

**Что проверялось/корректировалось человеком:**
- Выбор конкретных версий зависимостей и устранение уязвимостей
  (`npm audit`: заменён `vitest@2` → `vitest@5` из-за уязвимости в `@vitest/mocker`/`esbuild`).
- Исправление предупреждения Vite о `__dirname` в ESM-конфиге (`import.meta.dirname`).
- Исправление устаревшей опции `baseUrl` в `tsconfig` (TS 6: `paths` без `baseUrl` требует
  относительных путей `./src/*`).
- Ручная проверка: `tsc -b` (типы), `oxlint` (линт), `vite build` (продакшн-сборка),
  прямые curl-запросы к `/api/org-tree` (в т.ч. `scenario=empty`/`scenario=error`) —
  для подтверждения, что сгенерированный код реально работает, а не просто «выглядит правильно».
- Архитектурные решения (react-query вместо самописного кэша, styled-components вместо
  CSS-модулей, структура монорепозитория, модель клика/двойного клика для сортировки)
  зафиксированы и обоснованы в ADR — они принимались осознанно, а не слепым принятием
  первого предложенного AI варианта.
- Функциональная проверка этапов 02-03 сделана не только юнит-тестами: через headless
  Chromium (Playwright, временно, без сохранения в зависимости) реально открывалась
  страница, переключался вид, кликались заголовки для сортировки, вводился текст в
  фильтр и проверялось, что выбор строки в таблице подсвечивает узел в дереве —
  со скриншотами каждого шага.
- Эта проверка на этапе 03 нашла реальный баг в сгенерированном коде, а не только
  подтвердила рабочее поведение: AI-реализация fade-анимации задавала один и тот же
  `transition: background-color 1.5s` на включение и выключение подсветки. По коду
  это выглядело правильно, но при живом прогоне в браузере (снятие computed-стиля
  сразу после патча) вспышка оказалась почти невидимой — включение подсветки тоже
  анимировалось те же 1.5с и обрывалось через 60мс, набирая лишь пару процентов
  яркости. Исправление: асимметричная длительность (`0s` на включение, `1.5s` на
  затухание) — задокументировано как техническая деталь в
  [ADR-005](docs/adr/005-live-updates-transport-and-recompute.md), а не скрыто.
  Без реального запуска в браузере этот баг остался бы незамеченным — тесты и
  тайпчек его не ловят, т.к. это чисто визуальный эффект синхронизации CSS-переходов.

Раздел будет дополняться по мере выполнения этапа 04.
